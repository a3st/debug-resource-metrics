# Debug Resource Metrics

CPU, память и графики времени работы в боковой панели **Run and Debug** в VS Code.

## Возможности

- Панель открывается при запуске отладки.
- Отображаются CPU, резидентная память и время работы процесса.
- Графики CPU и памяти по времени работы используют тему редактора.
- Поддерживаются несколько сессий и история завершённых отладок.
- Локализации **en-US** и **ru-RU** выбираются по языку интерфейса VS Code.

## Установка и использование

1. Откройте **Extensions → ⋯ → Install from VSIX…** и выберите собранный `.vsix`.
2. Запустите отладку и раскройте **Ресурсы процесса** в разделе **Run and Debug**.
3. Если отладчик не сообщает PID, нажмите **Выбрать PID процесса**.

PID определяется из события отладчика или attach-конфигурации. Для Node.js и
Python дополнительно используется evaluate; иногда требуется остановка на breakpoint.

## Настройки

| Настройка | По умолчанию |
| --- | --- |
| `debugResourceMetrics.sampleInterval` | `1000` мс между измерениями |
| `debugResourceMetrics.historySize` | `180` точек графика |
| `debugResourceMetrics.autoReveal` | `true` |

## Об измерениях

**CPU:** 100% соответствует одному занятому ядру; значение может превышать 100%.
**Память:** RSS / working set в МиБ. **Время работы:** с начала отладки, включая
паузы на breakpoint. Дочерние процессы измеряются отдельно.

Сборщики поддерживают Windows, Linux и macOS. При работе через SSH, WSL или
контейнер PID должен принадлежать машине, где выполняется расширение workspace.
История хранится в памяти до перезагрузки окна или расширения. При запуске новых
сессий в списке остаются пять завершённых отладок и все активные.

## Разработка

Нужны Node.js с npm и Python 3 для сборки VSIX.

```sh
npm ci
npm test
npm run package
```

Нажмите **F5**, чтобы открыть Extension Development Host. TypeScript компилируется
в `out/`; для работы расширения npm-зависимости не нужны.
